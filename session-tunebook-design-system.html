05 / Patterns

Built for actual sessions.

05 — 06
Capture a tuneTitle → optional ABC or paste → detect key, meter and type where possible → review → save. Permit an incomplete entry.
Learn a tuneOpen score → play or slow playback → mark tricky bars or personal variation → return to the same place.
Build a setAdd tunes → order them → note key changes and transitions → use continuous print / session view.
Share / exportShare a link, export ABC and print a clean PDF. Keep source and attribution visible.

Reading and editing

  • Reading is the default. Editing is explicit and reversible.
  • Offer rendered score, ABC, or split view; remember the user's last view.
  • Never silently overwrite a tune variation or another person's source.
  • Display key changes and repeat structure in the notation itself.

Accessibility and print

  • Keyboard access for every action; visible focus and named icon buttons.
  • Meet WCAG AA contrast for text and controls; do not use color alone for state.
  • Support 200% zoom without clipping controls; prefer horizontal score navigation over illegibly small staves.
  • Print in true black on white with no app chrome; repeat tune title on page breaks.

Domain components

TuneSheet owns title, metadata, score and source. NotationViewport owns scale and playback position. ABCEditor owns text and validation. SetList owns tune order and transitions.

Architecture decisions

Store source ABC separately from parsed metadata and renderer output. Keep aliases, variations and provenance as first-class records. Use a real ABC/notation renderer; the specimen's music symbols are intentionally illustrative.

Suggested first slice: searchable tune library, tune sheet, ABC import/edit, set builder, clean print view. Add playback and advanced engraving only when the core reading experience is sound.
